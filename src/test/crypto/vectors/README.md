## `x25519Rfc7748.json`

58 cases of the same shape, generated by `x25519Rfc7748Gen.py` (`python3 -I x25519Rfc7748Gen.py > x25519Rfc7748.json`):
a bigint RFC 7748 section 5 ladder. Each of the 40 non-zero cases must equal `openssl pkeyutl -derive`,
and each of the 18 all-zero cases is refused by OpenSSL (or derived as zeros); any other OpenSSL refusal
or mismatch aborts the generation, as does coverage below 40 cross-checked cases. Groups: `Rfc7748Ktv` 6 (sections 5.2
and 6.1, as printed in the RFC), `ScalarClamp` 15, `PointHighBit` 9, `NonCanonicalPoint` 14 (u >= p),
`LowOrderPoint` 14. The `iterated` object holds the RFC 7748 section 5.2 results after 1 and 1000
iterations (1,000,000 is not run).

## Semantics

- `shared` is the raw output of X25519(`private`, `public`) as RFC 7748 section 5 defines it. For
  low-order points that is 32 zero bytes.
- `checkRawX25519` (raw kernel, `void`, cannot refuse): every case, all-zero ones included, must equal
  `shared`. This is the contract of the future `x25519ScalarMult(output, scalar, point)`.
- `checkSharedSecretX25519` (API): an all-zero `shared` must be refused (RFC 7748 section 6.1;
  `msX25519SharedSecret`). Wycheproof marks those cases `acceptable`, which would also allow returning
  the zeros; this API does not. Every other case, `acceptable` ones too, must return exactly `shared`;
  Wycheproof would also allow refusing them.
