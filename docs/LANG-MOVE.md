# Move Semantics — Design & Implementation Phases

MetaScript's `move` keyword is an ownership transfer directive. It forces sink semantics (no copy) and zeroes the source to prevent double-free.

```ms
const y = move x;        // y owns the data, x is zeroed
y = move x;              // old y destroyed, y = x's value, x zeroed
return move data;         // caller takes ownership, local zeroed
consume(move buffer);     // callee takes ownership, caller's var zeroed
{ name: move s }          // literal takes ownership, s zeroed
[move a, move b]          // array takes ownership, a/b zeroed
```

## Ownership Model — Reference Alignment

MetaScript follows the reference compiler's ownership model exactly. Every value-type variable (strings, arrays, structs with destructors) has **exactly one owner**. The DRC analyzer (`src/analyzer/inject.ms`) decides at each use site which operation to emit.

### The Five Zero-Copy Tools

The reference compiler provides 5 mechanisms to avoid deep copies. Our equivalents:

| # | Reference | MetaScript | C Output | Description |
|---|-----------|------------|----------|-------------|
| 1 | `sink` param (auto) | `DrcMode.Consumed` | callee owns, no copy | DRC detects last-use at call site → move instead of copy |
| 2 | `move(x)` / `ensureMove(x)` | `move x` keyword | `wasMoved(x)` after transfer | Explicit ownership transfer, source zeroed |
| 3 | `var` param | `ccgIntroducedPtr` | `T*` pointer param | Mutable borrow — callee modifies caller's variable |
| 4 | `lent` return | (not yet implemented) | return by reference | Read-only borrow of internal data |
| 5 | `.cursor` pragma | `NF_CURSOR` flag | no copy, no destroy | Non-owning reference — borrows without taking ownership |

### How the DRC Chooses

At every use site, the DRC analyzer makes a binary decision:

```
Is this the LAST use of variable x?
├── YES → MOVE (sink): transfer payload pointer, emit wasMoved(x)
│         Zero cost. No allocation. x becomes invalid.
│
└── NO  → COPY (deep): allocate new payload, memcpy data
          O(n) cost. Both x and dest own independent payloads.
```

The `isLastReadSafe()` function in `inject.ms` performs this analysis. The reference compiler's `injectdestructors` pass does the same check.

### Why Deep Copy (Not Refcounting)

The reference compiler uses **deep copy** for `=copy`, not shared payloads with refcounting:

| Aspect | Deep copy (reference + ours) | Refcounting (rejected) |
|--------|------------------------------|------------------------|
| Payload ownership | Always unique — one owner | Shared — multiple owners |
| `=destroy` | `free(p)` immediately | `if (--rc == 0) free(p)` |
| Mutation safety | Always safe | Needs COW check at every mutating op |
| `=copy` cost | O(n) — allocate + memcpy | O(1) — incref |
| How often copies happen | **Rare** — DRC converts most to moves | **Rare** — same DRC |
| Bug surface | Small | Large (miss one COW → corruption) |

**Key insight**: Since the DRC optimizer converts most assignments to moves (sink), deep copies are rare in practice. Paying O(n) for rare copies is better than risking COW bugs on every mutation.

The reference runtime confirms: the sequence payload base is `{ cap: int }` — no `rc` field. Every payload is uniquely owned.

### Lifecycle Operations

Each value type has 4 operations generated by the DRC:

| Operation | Reference | Our C Macro | When |
|-----------|-----------|-------------|------|
| `=destroy` | Free payload + destroy elements | `msArrayDestroy(arr)` / `msStringDestroy(s)` | Scope exit, reassignment |
| `=copy` | Allocate new payload, copy elements | `msArrayStringCopy(d, s)` / `msStringCopy(&d, s)` | Source still alive after use |
| `=sink` | Destroy old dest, bitwise move | `msArrayStringSink(d, s)` / `msStringSink(d, s)` | Replaces destroy+assign pair |
| `=wasMoved` | Zero the variable (len=0, p=NULL) | `msArrayWasMoved(arr)` / `msStringWasMoved(s)` | After ownership transferred out |

### Literal Protection

The reference uses `strlitFlag` (high bit of `cap`) to mark compile-time string/seq literals. Literals are never freed — `=destroy` checks the flag and skips. Our equivalent: `msIsLiteral(s)` checks for static string data.

Mutation of a literal triggers copy-on-write (allocate fresh payload, copy data). This is the ONLY COW in the system — runtime payloads are never shared.

## Compiler Equivalent

MetaScript `move x` = `ensureMove(x)` in production compilers.

Production compilers have TWO move mechanisms:

| | `move(x: var T)` | `ensureMove(x: T)` |
|---|---|---|
| Kind | Normal function | Magic directive |
| isLastRead check | YES — falls back to copy | BYPASSED — forces move |
| Error | None — silently copies | `errFailedMove` if copy would be needed |

MetaScript only has the keyword form (`move x`), which maps to `ensureMove`. The implicit move-on-last-read already handles the `move()` function equivalent via the analyzer's `isLastReadSafe` check.

## ~~Phase 3: Aliased Move Protection~~

**Status: DONE.**

### The Problem

```ms
y = move x;         // Non-aliased: destroy(y); y = x; wasMoved(x); — SAFE
x = move x.field;   // Aliased: destroy(x) destroys x.field BEFORE reading it!
```

### Solution: Capture Pattern

Production compiler's `destructiveMoveVar()` generates: `let tmp = v; wasMoved(v); tmp`

Our equivalent for `x = move x.field`:
```
const $moveTmp = x.field;     // 1. Capture field value
wasMoved(x.field);            // 2. Zero field (so destroy(x) won't touch it)
destroy(x);                   // 3. Safe destroy (field zeroed)
x = $moveTmp;                 // 4. Assign captured value
```

### Detection

Use existing `deepAliases(leftD.name, md.moveArg)` — returns true when RHS references the dest variable. Already works for MemberExpr and ArrayAccess (via `nodeReferencesVar`).

### Special Cases

- **Self-move** `x = move x` → no-op (production compiler: `nkEmpty`)
- **Aliased identifier** `x = move x` → caught by self-move check above
- **Non-aliased** → standard path (Phase 1)

### Production Compiler Equivalent

Reference implementation `destructiveMoveVar(n)` logic:
```
result = stmtListExpr()
var temp = newSym(skLet, "blitTmp")
result.add letSection(temp, n)      # let tmp = n
result.add genWasMoved(n)           # wasMoved(n)
result.add temp                     # return tmp
```

Used inside `moveOrCopy()` when `aliases(dest, ri) != no`:
```
result = genSink(dest, destructiveMoveVar(ri))
```

- `emitSaveAssignDestroy`: no valid `idx`/`stmts` context available
- Literal fields/elements: same

## Phase 5: First-Write Sink Optimization

**Priority: LOW** — Performance optimization, not correctness.

### What

Skip `destroy(old)` when assigning to a variable that was declared without an initializer (null-init). The variable is zeroed — destroying it is a no-op.

```ms
let x: string;      // x is null/zeroed
x = move y;          // No destroy(x) needed — first write
x = move z;          // NOW destroy(x) needed — second write
```

### Implementation

**`src/analyzer/scope.ms`**: Add `NullInitVars` tracking:
```ms

// Functions: markNullInit, isNullInit, clearNullInit
```

**`src/analyzer/inject.ms`**:
- `processVarDecl`: when `d.initializer === null`, call `markNullInit(dctx, d.declName)`
- `processAssignment`: ALL RHS paths (MoveExpr, isFreshExpr, Identifier) check `isNullInit(dctx, leftD.name)` → skip destroy, then `clearNullInit`

### Production Compiler Equivalent

Reference implementation `genSink()` logic:
```
if (not inLoopCond and (isDecl or (isFieldAccess and isFirstWrite))) or
    isNoInit or isReturn:

```

`fastAsgn` = bitwise memcopy without calling `=destroy` on old value.
